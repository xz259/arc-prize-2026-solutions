# Startup-only private MoE serving adapter

This source candidate fixes private native mode3 before any model warmup or CUDA graph capture. It leaves the installed runtime, numerical inputs/scales, original FlashInfer Python getter/wrapper/custom-op registration, autotuner and native runner calls unchanged. The private library is the one that passed actual N25 layer23 byte/graph checks with a 1.0301× median paired complete-MoE speedup. This is permission to test serving, not measured serving benefit.

Only two imports are intercepted: exact `flashinfer.fused_moe.core` and the official vLLM FlashInfer warmup module. Original source bytes are hashed and compiled directly, preserving package/relative imports and ignoring stale bytecode. All other imports use normal resolution. On core import the adapter requires an empty getter cache, validates the admitted build and producer receipt, loads the absolute private DLL in its default mode0, supplies it to the unmodified getter via a one-shot generator, calls exactly `getter('120')`, and restores the generator. No active getter/cache is cleared. A setup-only module proxy checks the original include-root call and exact eight native init arguments, then returns the actual native object; it does not proxy forwards.

One official warmup wrapper verifies the actual48 routers, normal baseline config and namespace, then fixes mode3 before any warmup/capture, observes the original cache loader accepting all42 main plans, and verifies those effective plans remain identical after ordinary warmup. Early memory profiling therefore uses original mode0. The wrapper then restores all temporary startup functions. No cache is seeded/rewritten by this adapter; official warmup retains its ordinary save behavior. No per-step Python callback, allocations, synchronization or file writes are added. The native candidate's shape guards retain the original branches outside N1..32/E512/top10/noEP and the finalizer's exact BF16/H2560 geometry.

`settings.json` pins the passed native producer receipt (`322d4725…de6707`): all210 direct and50 graph checks passed. The adapter rechecks this receipt and current native/source identities before loading the private library. This binds the actual native softmax top-k producer, not an upstream-source assumption. Finite ties, active nonfinite values, all/mixed padding and same-address graph mutations are separate cases. Invalid duplicate sentinels are allowed by the mapper; duplicate valid expert IDs are not.

Startup receipts are `<candidate>/private-startup/<pid>.json`, schema `arc3.private-moe-serving.startup.v1`. Use the live GPU worker's receipt after `state=warmup-verified`, with matching boot/PID/start_ticks and owner ancestry. It includes the actual native init, module hash/mode, source settings hash, restored hooks, all48 router inventory and42 plans, `namespace`, and `cache_path`. The loaded library remains fixed until process exit; no hot mode switching or CUDA recapture. A startup failure retains native handles and marks the process unsafe to reuse.

The baseline stage keeps compile_sizes=[], normal FULL capture sizes1,2,4,8,16,24,25,30,32, N30/context40K/.95/MTP0/no prefix cache, exact deterministic module and all persistent-state code. It does not inherit the failed exact-compile experiment. `launch_scaling.py start` remains nonblocking: candidate-server.json is startup identity, not API readiness. Parent ownership/readiness checks must wait for model readiness plus the correct verified worker receipt. Fresh startup only; never invoke inherited baseline stop actions without separate owner verification.

Before model loading run this package's18 CPU tests, the stage's4 lineage tests, and `preflight.py --output <fresh-receipt>` through the pinned runtime wrapper with the adapter disabled. Preflight reads exact sources/build/producer hashes but neither loads a native module nor constructs a model. Actual runtime import smoke is still required before long startup. On a fresh serving child, set `ARC3_PRIVATE_MOE_SERVING=1`, absolute settings/receipt paths, and prepend `bootstrap` then this package to existing runtime PYTHONPATH; the stage launcher supplies these after the wrapper.

Before unprofiled ABBA, excluded short N25/N30 profiles must show actual mode3 device symbols in FULL graph replay, with large-prefill original fallback and small/padded-tail coverage. Startup host mode/config/cache identity alone does not prove graph dispatch. Preserve existing continuation/eviction correctness, allocator/preemption checks and exact frozen throughput wave parameters. No launch/upload/GPU execution was performed while preparing this package.
